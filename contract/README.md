# contract

The interface between `sdsim` and `sdlab`: what a lab spec may contain and what a catalog entry must declare. Released as an artifact and vendored into `sdlab/contracts/sim/` (PLAN 5.4). Version 0.1.0 is in preparation (S-010 is the schema and the fixtures; S-010b adds the generated catalog and the release).

| File | What it is |
| --- | --- |
| `lab-spec.schema.json` | JSON Schema (2020-12) for the structure of a lab spec. Hand-written. `additionalProperties: false` at every level |
| `descriptor.schema.json` | What a component, edge policy or scenario declares about itself: parameters with unit, range and default, metrics, honesty label with evidence or assumption (ADR 0003 #1) |
| `RULES.md` | Which checks are schema, which are validator rules, which need the catalog |
| `CHANGELOG.md` | Contract changes and what `sdlab` must do |
| `src/` | The YAML loader (reads YAML the way PyYAML does) and the two validators, used by tests now and by the lab runtime and CLI later |
| `fixtures/valid/caching-basics.yaml` | The real sdlab lab, with `keys` and `skew` under `traffic` (R24) |
| `fixtures/cases.yaml` | 104 cases: a change to that lab as patch operations plus the expected verdict |
| `fixtures/descriptors.yaml` | 19 descriptor cases |
| `fixtures/dialect/` | 52 YAML snippets and how PyYAML reads them (`expected.json`, regenerated by `make_expected.py`) |
| `scripts/check_against_sdlab.py` | Runs every case through sdlab's own validator and reports disagreements |

## Checks

```bash
npm test                                                   # schema verdicts, descriptors, YAML dialect
python contract/scripts/check_against_sdlab.py ../sdlab    # the same cases through sdlab's validate.py (needs PyYAML)
python contract/fixtures/dialect/make_expected.py          # regenerate the PyYAML expectations after editing snippets.json
```

## The case format (so `sdlab` can mirror it)

Each entry of `fixtures/cases.yaml` has a `name`, a `patch` (a list of `{op: add|remove|replace, path, value}`; the path is a JSON pointer, `-` appends to a list; RFC 6902 reduced to these three operations) applied to `fixtures/valid/caching-basics.yaml`, and:

- `schema: valid | invalid`, the verdict of the JSON Schema; for invalid cases `at` (the JSON pointer of the first problem), `keyword`, `property`;
- `sdlab: <text>` on a schema-valid case that sdlab's validator still rejects, with the text of its message: a rule JSON Schema cannot express (cross-field, ordering, references, anti-leak);
- `differs: <reason>` where the schema and sdlab's validator disagree today (the schema is stricter, or sdlab does not know a new field yet).

## YAML dialect

`sdlab` parses with PyYAML (YAML 1.1: `yes`, `no`, `on`, `off` are booleans, `1_000` is an integer, a duplicate key keeps the last value). `src/yaml.ts` selects the `yaml` package's 1.1 mode and patches the two places where it differs from PyYAML (the words `y` and `n`, and exponents without a dot and a sign). Two exotic scalars still differ (see the test). Write ids and words that might be read as booleans in quotes; the fixtures do.
